    返回结构速查 —— 每个接口回什么

    


      
接口 → 返回

      

        http
        
GET     /api/kv/:scope           → { "data": Row | null }
PUT     /api/kv/:scope           → { "data": Row, "created": true, "changed": ["tagInt1"] }
PATCH   /api/kv/:scope           → { "data": Row, "changed": ["tagInt1"] }
DELETE  /api/kv/:scope/:uid      → { "deleted": 1,  "data": Row }
DELETE  /api/kv/:scope?all=1     → { "deleted": 12, "scope": "package" }
GET     /api/kv/:scope/list      → { "items": [Row], "page": 1, "size": 20, "total": 3, "hasNext": false }
GET     /api/kv/:scope/:uid/log  → { "items": [Log], "page": 1, "size": 20, "total": 2, "hasNext": false }
POST    /api/user/profiles       → { "profiles": [ { "uid": 42, "nickname": "…", "avatar": "…" } ] }

      

      
    
        
  • GET 没建过回 data: null，不是报错 —— 别当成失败处理。
    • 
        
  • PUT 是整行覆盖，没写的字段会被清空；日常改数据用 PATCH。
    • 
        
  • PATCH 的 inc 也一样，新值直接就在 data 里，不用再查一次。
    • 
        
  • DELETE /:uid 回带被删掉的那一行，客户端可以据此撤销。
    • 
        
  • ?all=1 删的是整个 scope（所有人的格），必须显式带上。
    • 
        
  • list / log 都带 hasNext，分页不用自己算 page * size < total。
    • 
      


      
Row —— 一行数据（/api/kv 里那个「格」）

      

        json
        
{
  "uid": 42,
  "scope": "package",
  "isPublic": false,
  "openEdit": ["tag_int1"],
  "tagTinyint": 1,
  "tagInt1": 100,
  "tagInt2": 0,
  "tagBigint": 0,
  "text1": "我的背包",
  "text2": null,
  "textLong": null,
  "extra": { "items": ["sword"], "gold": 1000 },
  "expiresAt": "2026-10-17T12:00:00.000Z",
  "createdAt": "2026-10-10T12:00:00.000Z",
  "updatedAt": "2026-10-10T12:00:00.000Z"
}

      

      
    
        
  • uid / scope —— 这一格归谁、属于哪个业务。
    • 
        
  • isPublic —— false 时只有属主和作者看得见。
    • 
        
  • openEdit —— 别人能改哪些字段的白名单，空数组 = 只读。
    • 
        
  • tagTinyint / tagInt1 / tagInt2 / tagBigint —— 数字标签，给筛选用；也可以是「剩余血量」那种状态。
    • 
        
  • text1 / text2 / textLong —— 上限 128 / 512 / 1024 字符。
    • 
        
  • extra —— 任意 JSON，序列化后不超过 2048 字节；永远不在 openEdit 里，别人改不了。
    • 
        
  • expiresAt —— 创建时定死（1~30 天），任何编辑都不续期。
    • 
      


      
Log —— 改一次留一条

      

        json
        
{
  "id": 901,
  "dataId": 77,
  "actorUid": 42,
  "action": "update",
  "changed": ["tag_int1", "text_1"],
  "before": { "tag_int1": 100, "text_1": "旧值" },
  "after":  { "tag_int1": 90,  "text_1": "新值" },
  "createdAt": "2026-10-10T12:00:00.000Z"
}

      

      
    
        
  • actorUid —— 真正动手的人（作者替玩家改时就是作者）。
    • 
        
  • action —— "create" 或 "update"。
    • 
        
  • changed —— 这次动了哪几个字段，名字和 openEdit 一样。
    • 
        
  • before / after —— 只含被改字段的前后值，不是整行快照。
    • 
      


      
出错

      

        json
        
{ "error": { "code": "invalid_param", "message": "text1 超过 128 字" } }

      

      
    
        
  • 所有失败都是这个形状，按 code 判断，别按 message 匹配。
    • 
      


      

        接口参数用驼峰（tagInt1），但 openEdit 和 changed 里装的是
        数据库字段名（tag_int1）—— 这两个最容易写反。
