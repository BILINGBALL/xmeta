# 联机 Demo

一个能直接发布到 B站 toy 的联机示例，用的是 xmeta 的身份服务和联机数据接口。

页面里没有服务器、没有数据库，也没有任何密钥。玩家点一次「申请联机凭证」，
就能在同一个大厅里看到彼此、聊天、一起打世界 Boss、互相串门、各自存背包。

- toy slug：`b15pXRp8Ak4eBelk`
- client_id：`xmeta_OXSY7nxlpKooXGd0oS95Cg`（已写进 `demo.js` 顶部的 `CONFIG`）

## 它能做什么

| 标签 | 功能 | 用到的 xmeta 能力 |
|---|---|---|
| **大厅** | 在线玩家、房间号进房、开自己的大厅、聊天（可往前翻）、小窝人气榜 | 单条读写、`inc`、`list`、改动日志、profiles |
| **世界 Boss** | 全服共用血量、攻击、累计伤害榜、重置 | `inc` 扣血 + 自己伤害行 `inc`、`openEdit`、列表排序 |
| **我的** | 匿名身份、私有背包、公开小窝、串门计数、改动记录 | 私有/公开数据、`extra`、`DELETE`、`ttl` |
| **调试** | 请求日志、凭证 payload、**联机凭证管理（重新申请 / 清除）**、原始数据 | —— |

未连接时只能看到介绍页和「申请联机凭证」。

### 大厅里的二级标签

二级标签和内容在同一个卡片里（标签嵌在容器顶部），大厅页分成四个二级标签，
省得房间卡和列表把页面撑太长。默认是「聊天」：

| 二级标签 | 内容 |
|---|---|
| **聊天** | 大厅消息、加载更早 |
| **房间** | 我的大厅（房间号 / 标题 / 展示开关）、大厅列表、搜索进房 |
| **小窝** | 小窝人气榜、去串门 |
| **在线** | 在线玩家、串门入口、刷新 |

下面的「房间号、标题和展示」都在 **大厅 → 房间** 里操作。

### 房间号、标题和展示

- **房间号是 6-8 位数字**（接口字段 `tagBigint`，整数字段；输入校验 6-10 位）。
  新建房间时随机生成并查重。一个人只能有一间（一个 scope 一人一条）；再开一次
  会重置自己那一间，房间号、标题和展示开关保留。
- **标题**存在 `text2`，房主可以改（最多 40 字）。
- **展示开关**是 `tagTinyint`：`1` = 在大厅列表展示，`0` = 不展示。
  不展示只是**不进列表**，不是私密：房间仍然是 `isPublic: true`，按房间号或
  标题都能搜到，知道号码的人都能进。之所以不做私密，是因为 xmeta 的 KV 里
  非公开的行别人读不到，也就没法共享。
- **大厅列表**只拉展示中的房间（`?tagTinyint=1`）。
- **搜索 / 进房**：输入 6-10 位数字按 `tagBigint` 精确查；输入其它文字按 `text2`
  标题模糊搜（服务端 `?q=`）。房间号唯一，找到就直接进；标题可能多条，
  结果列在「搜索结果」里，点「进房」。
- **不填房间号**：进入页面时会自动挑**最早创建**的、展示中的大厅。这只是默认
  收敛的约定，不是「官方大厅」。
- **开自己的房**：大厅 → 房间 → 右上角「＋ 新建」，在弹窗里填标题、
  选是否展示，点「创建」。已有自己的房间时房间号会保留，只重置血量和聊天；
  没有就生成一个新号码。
- 「调试 → 重新挑一间大厅」= 清掉本地记的房间，再按「最早创建」挑一次。

## 数据是怎么放的

一个用户在一个 scope 下只有一条数据。普通玩家每人 **3 条**：`damage`、`home`、`bag`；
开大厅的人多一条 `lobby`（大厅是所有人共用的）。  
大厅和伤害分开，是因为「聊天/心跳」和「排行榜」的增长方式完全不一样。

### `lobby` —— 一个房间一条

一个房间就是一条 `lobby` 数据，房主是它的属主。开房时随机生成 6-8 位房间号；
所有人往这一条上写：

| 字段 | 用途 |
|---|---|
| `tagTinyint` | `1` = 在大厅列表展示；`0` = 不展示（仍然公开，可按房间号/标题搜到） |
| `tagInt1` | 心跳。每 12 秒换一个值，改一次就在日志里留一条 |
| `tagInt2` | Boss 血量。攻击时 `{ inc: { tagInt2: -伤害 } }` |
| `tagBigint` | 房间号（整数；入网收字符串或小整数，**出网一律是字符串**，6-10 位） |
| `text1` | 聊天。谁发消息就写自己那句话，历史从 `changed=text1` 的日志里翻页读 |
| `text2` | 房间标题，房主可改（最多 40 字） |
| `extra.version` | 房间版本标记 `xmeta-room-v3`，只有房主能改 |
| `openEdit` | `["text1","tagInt1","tagInt2"]` —— 所以别人能聊天、心跳、打 Boss，改不了房间号/标题/展示开关 |

**在线状态不另存数据**：45 秒内在这条数据的日志里出现过的人，就算在线。

**聊天不另存数据，但按字段筛着读**：每条改过 `text1` 的日志就是一句话。
页面用 `?changed=text1` 只取聊天记录，不会被心跳挤掉；先取最近 100 条，
点「加载更早的消息」再往前翻页（页面上最多留 1000 条已加载的）。

### `damage` —— 一人一条，公开

世界 Boss 的伤害榜**不从日志算**。攻击次数可以是无限的，玩家数是有限的：

| 字段 | 用途 |
|---|---|
| `tagInt2` | 自己累计打了多少伤害，攻击时 `{ inc: { tagInt2: 伤害 } }` |
| `isPublic` | `true`，排行榜要读得到 |
| `openEdit` | `[]` —— 只有自己能改 |
| `ttl` | 30 天，攻击时顺手续期 |

排行榜请求：

```http
GET /api/kv/damage/list?page=1&size=100&sort=tagInt2&order=desc
```

**一页就够前 8 名**，跟一共打了多少次无关。列表最多缓存 30 秒；自己刚打的那一下
以写接口的返回为准，先本地更新，不用等缓存。

> `damage` 是 **toy 级**的，不区分大厅。换大厅不会清零累计伤害；重置 Boss 也只
> 回血，不清榜。要按「轮次」清零的话，另起一个 scope 或者让每人删掉自己那条。

> Boss 血量仍然在大厅那一条的 `tagInt2` 上（世界 Boss 是所有人写同一条公共数据）。
> 榜单上的「累计」是每人 `damage` 行的总和；顶部「本轮 Boss 已掉 X」是当前血量的
> 差值。重置 Boss 只回血，榜单累计不清零。

### `home` —— 一人一条，公开

| 字段 | 用途 |
|---|---|
| `text1` | 门牌 |
| `text2` | 主题 key（樱花 / 月夜 / 营地 / 猫屋 / 太空） |
| `tagInt1` | 被串门次数 |
| `openEdit` | `["tagInt1"]` —— 别人只能给这个数字 +1 |

### `bag` —— 一人一条，私有

| 字段 | 用途 |
|---|---|
| `tagInt2` | 金币，用 `inc` 加 |
| `extra` | 道具数组，最多 12 件（`extra` 序列化后 ≤ 2048 字节） |
| `isPublic` | `false` |
| `openEdit` | `[]` —— 谁都不能改 |

> **世界 Boss 的血量在谁名下？**
>
> 血量是**公共数据**，存在大厅那一行上，归开这间大厅的人（房主）。所有人攻击时
> 改的都是这一行的 `tagInt2` —— 这是世界 Boss 的用法（见 GUIDE 场景二），不是把
> 谁的背包改了。`openEdit` 只开了 `text1 / tagInt1 / tagInt2` 三个字段，房主的
> 背包、小窝、`extra` 都碰不到。伤害榜是每个人自己的 `damage` 行，跟房主无关。
>
> 页面在 Boss 卡片下面会写明「房主 uid X」。单人测试时如果不想写到别人的行上，
> 点大厅 → 房间 → 右上角「＋ 新建」，那间大厅就归你。
>
> 从 v1 升到 v2 时换了房间标记：旧的 v1 大厅不会再被使用，避免接着打一个
> 字段含义对不上的旧房间。旧房间的数据不会被删，只是不再被这里选中。

## 部署

1. 打开 B站 toy 后台，进入 `b15pXRp8Ak4eBelk`。
2. 把 `index.html`、`demo.js`、`xmeta-ui.css` 上传到同一层。
3. 发布。
4. 在 B站 App 或桌面 Web 里打开这个 toy，点「申请联机凭证」。
5. 在中心 toy 里选有效期（3 / 6 / 12 / 24 小时），允许，回来会自动兑换。

> **服务端也要一起更新。** 这次页面用到了这些新参数：
> `GET /api/kv/:scope/list?sort=tagInt2&order=desc`（排行榜取前 N）、
> `?tagBigint=123456`（房间号精确搜）、`?q=标题`（标题模糊搜），以及
> `GET /api/kv/:scope/:uid/log?changed=text1`（聊天只取消息记录）。另外还有
> `cache.del()` 的竞态修复、`sql/008` 的排序索引和 `sql/009` 的房间号索引
> （跑一次 `npm run db:migrate`）。
>
> 不更新服务端页面也能跑，但会退化：列表按 uid 返回、客户端排序，前 N 名可能
> 不准；房间号/标题搜索只能在前 100 条里本地过滤；聊天翻页会把心跳算进 total，
> 能读到但更慢。

- 聊天历史：第一页取最近 100 条消息；点「加载更早」能读到最老的消息
- 同一个人连发两条，第二条也有头像和昵称
- 攻击 Boss：服务端血量减少、自己那条伤害数据增加、榜单累计和血量对得上

- 倒计时：4 秒内没有任何心跳 / 轮询，剩余时间逐秒变化、不跳秒，有效期进度条连续减少

- 凭证到期：轮询自动停下，出现「重新申请」提示

- 430px 宽度下没有横向溢出，页面没有 console error / 未捕获异常

### 这次修的问题

**页面被旧响应覆盖。** 攻击、心跳、3 秒轮询是三个并发请求，响应到达顺序不保证。
攻击已经把血量写下去后，晚到的轮询 / 心跳响应可能还带着攻击前的行。现在每一行
都用服务端的 `updatedAt` 当版本号，比当前旧的响应直接丢掉。对应的浏览器测试
在不加这个判断时会稳定失败（实测 98736 ≠ 98682），加回来后通过。

**服务端单条读缓存的竞态。** 写接口删缓存时，如果正好有一个读请求回源到一半，
它可能在删完之后把旧行又写回缓存，接下来 30 秒都读到旧血量。`cache.del()` 现在
会先等在途回源落地再删；仓库里加了 `test/cache.test.ts` 覆盖这个顺序。这个修复
要**重新部署服务端**才生效；页面这边的 `updatedAt` 判断不依赖它。

**聊天输入框和按钮。** 共用样式里 `.xm-btn` 是 `width:100%`，把发送按钮撑满了
整行。聊天栏里显式改回 `width:auto` + `flex:1 1 0%`，按钮不再挤掉输入框。

**连发两条看不到头像。** 原来为了省地方，同一个人连发会省略第二条的头像和昵称。
现在每条都完整显示。

**聊天读不出来。** 原来只读最近 100 条日志，心跳一多，旧消息就被挤掉。现在
`?changed=text1` 只取聊天记录，先读最近 100 条，点「加载更早的消息」按页往前翻。

**伤害榜算不准 / 翻不动。** 原来从日志聚合，1000 人打 10 次就是 1 万条日志，
既不准确也不现实。现在一人一条 `damage` 公开数据，攻击时只 `inc` 自己那条；
排行榜用 `?sort=tagInt2&order=desc` 一页取前 N 名，跟攻击次数无关。

**连点。** 攻击 / 打工 / 捡道具默认 5 秒冷却；冷却期间按钮显示剩余秒数，点下去
只提示等待，不会发请求。这是前端限制，服务端的写限流（每人每分钟 120 次）仍然
是最后一道。要防脚本直接打接口，需要按 uid + 动作在服务端做更细的限流。

**串门次数先变 1 又变回 0。** 串门后的 PATCH 返回新行，先更新本地；但小窝列表
有最多 30 秒缓存，下一轮刷新会把旧行盖回来。现在列表行和本地行按 `updatedAt`
取较新的那份，旧的缓存不会把次数刷回去。串门本身也改成了真弹窗：显示对方的
头像、昵称、主题、门牌和被串门次数，+1 时数字会弹一下。

**倒计时不平滑。** 倒计时一直和心跳 / 轮询无关：剩余时间只来自凭证的 `exp` 和
本地 `Date.now()`。以前用 `setInterval(1000)` 刷文字，定时器漂移会偶尔跳秒；
现在每 200ms 对一次表、只在显示值变化时写 DOM，并加了一条有效期进度条，
CSS transition 把 200ms 的步进抹平。浏览器测试在 4 秒内不跑任何网络请求，
验证倒计时仍然逐秒走、进度条连续减少。

**凭证管理挪到调试页。** 「我的」页只留身份和剩余时间；重新申请 / 清除本地凭证
放到「调试 → 联机凭证」，和凭证 payload 在一起。

**大厅里的房间系统。** 大厅页加了四个二级标签（聊天 / 房间 / 小窝 / 在线），
标签嵌在内容卡片顶部，默认显示聊天；之前很长的房间卡和大厅列表收进「房间」。
创建 / 重置大厅改成**弹窗**（填标题、选是否展示），不再在房间里常驻一个两步确认
按钮。房间号改成随机 6-8 位数字（存在 `tagBigint` 整数字段里），标题存在 `text2`
（房主可改），`tagTinyint` 做展示开关（`1` 展示 / `0` 不展示）。
大厅列表只拉 `?tagTinyint=1`；搜索用 `?tagBigint=`（房间号精确）或 `?q=`（标题
模糊），未展示的房间也能搜到。不展示不是私密，房间仍然是 `isPublic: true`。
服务端新增了这两个过滤参数和 `sql/009` 的房间号索引。

**UGC 内容安全。** 聊天、房间标题、小窝门牌在写入前都过 `toy.checkInputSafety`；
`rejected` / `unavailable` / 不支持 / 异常都不放行，只有 `passed` 才写入。
自动建房用固定标题「我的大厅」，不从昵称拼。详细见上面的「UGC 内容安全」。

### 还没法在这里自动测的

## UGC 内容安全

所有会被其他玩家看到的自由文本，在写入前都先调用平台的
`toy.checkInputSafety`（见 `toy-js-sdk-abilities`）：

| 入口 | scene | 写到哪里 |
|---|---|---|
| 大厅聊天 | `lobby.chat` | `lobby.text1` |
| 房间标题（创建 / 修改） | `room.title` | `lobby.text2` |
| 小窝门牌 | `home.motto` | `home.text1` |

- `passed === true` 才写入。
- `status === 'rejected'` → 提示「这段内容不能展示，换一句试试」，原文留在输入框。
- `status === 'unavailable'`、环境不支持、调用异常（含 307044 限流）→ **一律不放行**，
  提示稍后再试。文档明确 `unavailable` 表示检测没跑成，不等于通过。
- 只在**提交时**调用，不在每次按键时调用 —— 接口有配额，超了会抛 307044。
- 自动创建房间用固定标题「我的大厅」，不从昵称拼：昵称是平台侧 UGC，
  没有经过这里的检测。
- `text` ≤ 16384 字节；`scene` 只用 ASCII 业务标记。

> **这是客户端闸门。** 改过的客户端可以绕过它直接调接口；xmeta 服务端不做内容
> 审核。要做到服务端强校验，需要把同样的检测接到你自己的后端（平台提供的是
> toy 端能力）。

## 1000 个玩家、100 万条日志，现实吗？

分三种数据看：

**伤害榜**：现在跟日志无关。攻击一次 = 改两行：大厅血量 `inc` 一下、自己
`damage` 行 `inc` 一下。排行榜 = `sort=tagInt2&order=desc` 取一页。

- 1000 个玩家 = **1000 行** `damage` 数据；按分数排序取前 100 名 = **1 次请求**。
- 要显示全部 1000 人 = 10 页，10 次请求。
- 1 万玩家 = 100 页。这时候就不该在玩具前端拉全量了：通常只展示前 N 名，
  或者在你自己的后端做聚合。
- **百万玩家**：xmeta 的 KV 不是排行榜服务，单表 + offset 分页扛不住这种规模。
  把伤害汇总到你自己的后端 / Redis ZSET / 专用排行榜，xmeta 只负责把「这一刀」
  的增量传过去。

**聊天**：`changed=text1` 只取聊天记录，翻页不会被心跳挤掉。聊天本身是无限增长的；
页面只保留最近加载的 1000 条，更早的按需再拉。

- 一个玩具几千条消息：这个方案够用。
- 几十万条以上：日志表会很大，offset 分页也会越来越慢。生产上应该定期归档 /
  清理 `toy_data_log`，或者把聊天放到你自己的消息存储里（云存储 / 后端），
  xmeta 只做大厅的实时状态。

**服务端的账**：日志没有自动清理，攻击和心跳都会往里写。百万级写入之前，先给
`toy_data_log` 做保留策略（按时间分区 / 定期删除），否则查询和存储都会出问题。
这是服务端的运维，不是这个页面能解决的。

**一句话**：玩家数 × 每人一条汇总行是现实的（几千到几万，取决于数据库和索引）；
「每次攻击一条日志 + 客户端全量聚合」不现实。页面现在走的是前一种。

> 服务端已经加了 `sort` / `changed` 和 `sql/008` 的排序索引。没部署服务端时，
> 页面会退化成「列表按 uid 返回、客户端排序」，前 N 名可能不准；聊天翻页也会把
> 心跳算进 total。部署后才是完整效果。

## 几个要注意的地方

**列表有缓存。** `/api/kv/:scope/list` 在配了 Redis 的服务上最多缓存 30 秒。
小窝人气榜和伤害榜都会拿到稍旧的列表；自己刚写的那一条以写接口的返回为准，
先在本地更新。别人的伤害最多晚 30 秒显示，这是列表缓存的代价。

**在线取最近 100 条日志，聊天按字段翻页。** 在线状态只需要最近的心跳；
聊天用 `?changed=text1` 单独取，先 100 条，点「加载更早」再往前翻。
页面上最多保留 1000 条已加载的消息，更早的还能继续按需拉。

**冷却只在前端。** 攻击 / 打工 / 捡道具默认 5 秒一次，连点不会发请求；
但脚本直接调接口不受这个限制，最终靠服务端的写限流（每人每分钟 120 次）。
要按「动作」限流，得在服务端加。

**大厅房主 / 房间号 / 展示。** 大厅那一行归创建它的人（房主）。房主心跳会
顺手续期 30 天；房主长期不来，房间最多 30 天后过期，下次进来会重建。

- 不填房间号：自动进「最早创建」的、**展示中**的大厅。这只是默认收敛的约定。
- 想进指定房间：在大厅 → 房间 输入 6-10 位房间号，或标题关键字。
- 想开自己的：点大厅 → 房间 → 右上角「＋ 新建」，在弹窗里填标题、
  选展示开关。一个人只能有一间，再开一次会
  重置自己那一间；房间号、标题和展示开关保留。
- **展示开关只是不进大厅列表，不是私密。** 房间仍然是公开数据，按房间号或
  标题都能搜到，知道号码的人都能进。要真正的私密房间，xmeta 的 KV 模型做不到
  （非公开的行别人读不到，也就没法共享）。
- 大厅列表有 30 秒缓存；搜索/进房走 `tagBigint` / `q` 过滤，不受列表缓存里的
  其他房间影响。

**网络地址不能在页面里改。** `demo.js` 只在 `127.0.0.1` / `localhost` 下接受
测试脚本注入的 `apiBase`，线上页面不会走这条路 —— 否则别人给你一个带参数的
链接，就能把请求和凭证引到自己的服务器。

**凭证存在 localStorage。** `www.bilibilitoy.com` 下所有 toy 同源，别的 toy
理论上读得到。凭证绑定了 `aud`（只对这台 toy 有效），但玩完想清掉可以点
「我的 → 清除本地凭证」。

**不是长期存储。** 背包、家园是 7 天有效期；大厅和伤害行是 30 天。xmeta 只负责
交换数据，长期存档要作者自己存。

## 出问题看这里

| 现象 | 多半是 |
|---|---|
| 点了「申请联机凭证」没反应 | 不在 B站 App / toy 页面里，`toy.navigate` 不可用 |
| 回来之后还是未连接 | 强制刷新页面；确认 `clientId` 和 toy 对得上 |
| 页面显示「xmeta 服务暂时不可用」 | `https://www.oxth.com:8443` 不可达，或证书 / 混合内容被拦 |
| 和朋友看不到彼此 | 两人进了不同的大厅：把房主的房间号发给对方，让对方在「大厅 → 房间」里搜 |
| Boss 血量显示在别人的 uid 下 | 这间大厅是对方开的，Boss 血量是公共数据；想自己开一间，点大厅 → 房间 → 右上角「＋ 新建」 |
| 进房提示「不存在、已过期或不是当前版本」 | 房间号不对，或那间房是旧版 v1/v2 房间；让对方重新开一间 v3 房间 |
| 搜不到未展示的房间 | 先确认服务端已部署 `tagBigint` / `q` 过滤；没部署时只能在前 100 条里本地搜 |
| 「重新申请凭证 / 清除凭证」在哪 | 「调试 → 联机凭证」 |
| 打完 Boss 血量没动 / 数字对不上 | 先刷新页面。旧版本可能读到了晚到的旧响应；现在用 `updatedAt` 挡掉了，服务端缓存竞态修好后多端也会一致 |
| 伤害榜比实际打得少 | 旧版本从日志算榜，只覆盖最近一段；现在是一人一条 `damage` 数据。如果还是少，可能是列表 30 秒缓存，等一会儿或点「刷新」 |
| 聊天看不到更早的消息 | 去「大厅 → 聊天」，点消息上方的「加载更早的消息」。如果服务端还没部署 `changed` 参数，翻页会把心跳算进去，需要重新部署服务端 |
| 按钮显示「还要等 N 秒」 | 攻击 / 打工 / 捡道具的 5 秒冷却，等它走完 |
| 聊天发不出去 | 内容是 128 字以内；和上一条完全相同不会留日志 |
| Boss 打不动 | Boss 已经倒下，点「重置 Boss」 |
| 背包金币不涨 | 401 说明凭证过期了，重新申请 |
| 请求日志里一堆 401 | 凭证过期后还在轮询，重新申请后会恢复正常 |
